# План улучшений Hebrew Train

Дата: 19.10.2026. Основан на анализе кода версии 0.3.0 (ветка `main`).

Две жалобы пользователей, от которых отталкивается план:

1. **Задания скучные и не цепляют.** Сейчас это четыре варианта одного и того же упражнения «картинка → вспомни слово», слова выпадают случайно, прогресса в изучении не видно, игра никогда не заканчивается и ничем не награждает.
2. **Хочется играть оффлайн.** Приложение не является PWA: нет манифеста и service worker, при открытии без сети на телефоне показывается ошибка браузера.

## 1. Что показал анализ кода

### 1.1. Архитектура (кратко)

| Слой | Что есть | Состояние |
|------|----------|-----------|
| Оболочка | `App.tsx` переключает меню и четыре игры через `useState` | Нет роутинга и истории, кнопка «назад» на Android закрывает приложение |
| Игры | `Game1LetterChoice`, `Game2LetterInput`, `Game3WordChoice`, `Game4WordInput` | 4 файла по 210–310 строк, на 70 % дублирующие друг друга (шапка, блок статистики, модалка, таймеры) |
| Прогресс | `useScore` + `useLocalStorage`, ключ `hebrew-train-stats` | Хранится только `correct / total / percentage` на игру. Нет данных по словам, сессиям, дням |
| Данные | `src/data/words.json`, 159 слов, 8 категорий | Поле `difficulty` не используется игрой, поле `audioUrl` не заполнено |
| Мёртвый код | `useGameLogic`, `useMatching`, `anagramUtils`, `HebrewInput` | Не используются ни одним компонентом, но покрыты ~100 тестами |
| Сборка | Vite → `docs/`, деплой на GitHub Pages коммитом папки `docs/` | Работает, но нет PWA, нет CI |
| Тесты | 245 юнит-тестов на утилиты и хуки | Компоненты игр не покрыты вообще |

### 1.2. Почему задания скучные (конкретные причины в коде)

- **Чистый рандом вместо обучения.** `getRandomWord(words)` берёт любое из 159 слов, не исключая даже только что показанное. Нет понятия «новое слово», «учу», «выучил». Пользователь не чувствует, что продвигается.
- **Все четыре игры про одно.** Разница только в способе ввода ответа. Нет игр на ассоциацию «картинка ↔ слово» с несколькими объектами одновременно, нет памяти, нет темпа, нет соревнования с самим собой.
- **Игра бесконечна.** Нет раунда из N заданий, нет финального экрана, нет момента «я сегодня сделал». Выход только кнопкой «Назад».
- **Ошибка ничему не учит.** В играх-выборах после ошибки правильный ответ 2.5 секунды подсвечен зелёным, затем кнопки разблокируются, и клик по только что показанному ответу засчитывается как правильный (`addCorrect()`). Статистика накручивается, а запоминания не происходит.
- **Долгое ожидание.** После правильного ответа модалка висит 4–4.5 секунды. На 20 заданий это полторы минуты пустого ожидания.
- **Нет звука.** Для начинающих слово без произношения запоминается плохо, а транслитерация латиницей (`tapuach`, `cafe`) для русскоязычной пожилой аудитории мало помогает.
- **Задания на буквы бьют по новичку.** «Угадай букву» и «Впиши букву» в слове, которое пользователь ещё не знает, превращаются в угадайку. Эти игры полезны только для уже знакомых слов.

### 1.3. Проблемы в данных

- Дублирующийся `id: "wind"` (категории `objects` и `nature`): ломает ключи React и будущую статистику по словам.
- Опечатка: `бейца` записана как `בייצה`, должно быть `ביצה`.
- Слова с пробелом (`תפוח אדמה`, `לוח שנה`, `פח אשפה`, `שעון קיר`, `מכונת כביסה`, `שואב אבק`): `getRandomPosition` может выбрать пробел, и тогда «пропущенная буква» — это пробел, а бейдж «N букв» считает пробел буквой.
- Гереш в `ג׳ירפה` и `ז׳קט` может оказаться «пропущенной буквой», а при вводе с клавиатуры обычный апостроф `'` не проходит проверку `isHebrewText`.
- Неудачные эмодзи: голова = 🗣️, живот = 🤰 (беременная женщина), волосы = 💇 (стрижка), чашка = ☕ (совпадает с кофе), кастрюля = 🍲 (совпадает с супом). В игре «Угадай слово» одна картинка подходит двум словам.
- `difficulty`: 140 слов уровня 1, 19 слов уровня 2, ноль слов уровня 3. Поле фактически бесполезно.
- README говорит о 118 словах, реально 159.

### 1.4. Прочее

- `index.html`: `lang="en"`, заголовок `hebrew-train`, иконка Vite по умолчанию.
- `src/App.css` — остатки шаблона Vite (стили логотипа), не используются.
- Перемешивание через `.sort(() => Math.random() - 0.5)` в играх 1 и 3, хотя есть корректный `shuffleArray`.
- `package-lock.json` ссылается на приватный npm-реестр `npm.dev.wixpress.com` (658 ссылок, ни одной на `registry.npmjs.org`). Вне корпоративной сети `npm ci` зависает: любой другой разработчик или CI не сможет поставить зависимости. Нужно перегенерировать lock-файл с публичным реестром.
- `TESTING.md` и README расходятся с реальностью (235/245 тестов, 57/118/159 слов). Служебные файлы `BUILD_FIX_SUMMARY.md`, `UX_PLACEHOLDER_FIX.md` и т.п. лежат в корне.

## 2. Продуктовые решения

Решения ниже согласованы с автором, см. раздел 6 «Принятые решения».

### 2.1. Главная идея: не «игры», а «тренировка» со видимым прогрессом по словам

Центром приложения становится **личный словарь** пользователя. Каждое слово находится в одной из коробок (упрощённая система Лейтнера):

| Коробка | Смысл | Когда повторять |
|---------|-------|-----------------|
| 0 | Новое, не показывалось | — |
| 1 | Познакомился | в этой же сессии |
| 2 | Узнаю по картинке | через 1 день |
| 3 | Помню уверенно | через 3 дня |
| 4 | Выучено | через 7 дней |
| 5 | Закреплено | через 30 дней |

Правильный ответ с первой попытки поднимает слово на коробку выше, ошибка опускает на одну (не ниже 1). Какие слова и в каких играх показывать, решает один модуль `scheduler`, а не каждая игра отдельно. Новые слова вводятся порциями по 5 за сессию, чтобы не перегружать.

Это даёт то, чего нет сейчас: честный ответ на вопрос «сколько слов я уже знаю» и ощущение движения вперёд.

### 2.2. Структура сессии: раунд из 10 заданий + итоги

Любая игра идёт раундом из 10 заданий с прогресс-полосой «4 из 10» вверху. После раунда — экран итогов:

- список 10 слов с ✓/✗ и стрелкой «↑ выучено лучше» для слов, поднявшихся на коробку выше;
- 1–3 звезды за раунд (10/10, 8–9, меньше);
- кнопки «Повторить ошибки» (раунд только из слов с ✗), «Ещё раунд», «В меню».

Заменяет бесконечную игру с выходом по кнопке «Назад».

### 2.3. Что делаем с текущими играми

| Игра | Решение | Почему |
|------|---------|--------|
| 1. Угадай букву | **Оставить, но переназначить**: используется как шаг «первое знакомство» для слов из коробки 0–1 (слово показано полностью с подсветкой одной буквы, затем та же буква пропущена). Как отдельная карточка в меню убирается. | Отдельно скучно, как шаг знакомства со словом полезно |
| 2. Впиши букву | **Убрать как отдельную игру.** Её механика (одна буква с клавиатуры) становится подсказкой внутри «Напиши слово»: при второй ошибке открываются все буквы кроме одной. | Тренировка раскладки нужна немногим, а новичков отпугивает |
| 3. Угадай слово | **Оставить** как базовую игру для коробок 1–3. Убрать повторный клик после ошибки (ответ показывается, раунд идёт дальше, слово вернётся в этом же раунде через 3–4 задания). | Основная механика узнавания работает |
| 4. Напиши слово | **Оставить** как «продвинутую», предлагать только для слов из коробки ≥3. Добавить экранную ивритскую клавиатуру из 22 букв как альтернативу системной. | Для пожилых переключение раскладки — главный барьер |

### 2.4. Новые игры (на запоминание и ассоциации)

Приоритет сверху вниз. Для первых двух уже есть готовые и протестированные хуки/утилиты (`useMatching`, `anagramUtils`).

1. **Найди пары** (`matching`). Слева 5 картинок, справа 5 слов в случайном порядке, соединяем тапами. Самая любимая механика у возрастной аудитории: нет ввода, нет таймера, видно, что уже сделано. Ошибка только мигает красным и не наказывает.
2. **Собери слово** (`anagram`). Картинка, под ней пустые клетки по числу букв, ниже перемешанные плитки букв + 2 лишние. Тап по плитке ставит её в клетку, тап по клетке возвращает. Учит написанию без системной клавиатуры и справа-налево наглядно. Заменяет «Впиши букву» как шаг к письму.
3. **Мемори** (`memory`). 12 карточек рубашкой вверх: 6 картинок и 6 слов. Открываем по две, пара остаётся открытой. Классическая игра на память, формирует ассоциацию картинка ↔ слово лучше любого выбора из вариантов, при этом весело.
4. **Карточки** (`flashcards`). Картинка + кнопка «Показать слово» → слово, огласовка, озвучка, подсказка-ассоциация → самооценка «Знал / Не знал». Это самый быстрый способ знакомства с новыми словами, и единственный, где нет «неправильного» ответа. Используется для ввода новых слов в раунде.
5. **Верно / Неверно** (`speed`). Картинка и слово, половина пар подменена похожим словом из той же категории. Две большие кнопки. 60 секунд, счётчик серии, лучший результат сохраняется. Единственная игра на темп, даёт азарт и причину вернуться «побить рекорд».
6. **Послушай и выбери** (`listen`). Звучит слово, на экране 4 картинки. Требует озвучку (п. 2.6). Добавляет канал восприятия, который сейчас отсутствует полностью.

### 2.5. Режим «Тренировка дня»

Первая и самая крупная кнопка в меню. Планировщик составляет раунд из 10–12 заданий, смешивая игры:

- 3–5 новых слов через «Карточки» → сразу «Угадай букву» на них;
- слова к повторению по датам коробок через «Угадай слово», «Найди пары», «Собери слово»;
- одно-два слова коробки ≥3 через «Напиши слово» (если пользователь не отключил письмо).

Серия дней подряд (streak) с пламенем 🔥 на главном экране и дневная цель «1 тренировка». Пользователю не нужно выбирать, что делать: он открывает приложение и нажимает одну кнопку.

### 2.6. Ассоциации и память: что добавляем в данные слов

Расширяем `Word`:

```ts
interface Word {
  // существующие поля...
  nikud?: string;        // слово с огласовками: תַּפּוּחַ — показывается при знакомстве и в карточках
  mnemonic?: string;     // ассоциация на русском: «тапуах — тапок упал на яблоко»
  tags?: string[];       // тематические наборы для уроков: "kitchen", "morning", ...
}
```

- **Огласовки** (никуд) при первом знакомстве и в карточках. В остальных играх слово без огласовок, как в реальной жизни.
- **Мнемоника на русском** для каждого слова: короткая фраза-крючок. Это прямой ответ на запрос «образование ассоциаций». Черновик для всех 159 слов пишу я, автор проекта вычитывает (см. открытые вопросы).
- **Озвучка.** Этап 1: Web Speech API (`speechSynthesis`, голос `he-IL`). На iOS голос Carmit встроен, на Android нужен Google TTS с ивритом; оба работают оффлайн. Этап 2: записанные mp3 в `public/audio/` (159 файлов, около 1.5 МБ), кэшируются service worker, чтобы звук был у всех без зависимости от системы.

### 2.7. Отображение результатов и прогресса

Сейчас: в меню бейдж «15 / 20 (75%)» и полоска по играм; в игре два блока счёта (сессия и всё время), занимающие половину экрана.

Будет:

**Главный экран**
- Карточка «Мой словарь»: три числа крупно: «Выучено 23 · Учу 31 · Новых 105», кольцевая диаграмма.
- Серия дней 🔥 и «сегодня: 2 раунда, 18 из 20».
- Карточки игр с компактной строкой: «последний раунд ★★☆ · лучший 10/10 · точность за 7 дней 84 %».

**Внутри игры**
- Одна полоска «задание 4 из 10» с зелёными/красными сегментами за уже отвеченные задания.
- Никаких процентов и накопительных счётчиков: они уходят на экран итогов и страницу прогресса.

**Экран итогов раунда** — описан в 2.2.

**Страница «Прогресс»** (новая)
- Календарь активности за последние 12 недель (как в GitHub), выделены дни с выполненной тренировкой.
- Слова по категориям: 8 строк «Еда 18/28» с полосками.
- Таблица «Слова, с которыми трудно»: топ-10 слов по числу ошибок с кнопкой «Повторить эти слова».
- Список всех слов со статусом (коробка), фильтр по категории. Тап по слову: картинка, никуд, озвучка, мнемоника.
- Кнопки «Сохранить прогресс в файл» / «Загрузить из файла» (резервная копия, см. 3.3).

**Исправление честности счёта.** Задание засчитывается один раз: правильно с первой попытки = ✓, иначе = ✗. Повторный клик после показа правильного ответа не учитывается.

### 2.8. Доступность для пожилых (небольшие, но важные)

- Настройка размера шрифта «A / A+ / A++» (сохраняется), влияет на иврит и кнопки.
- Переключатель звука ответов (короткие мягкие сигналы) и озвучки.
- Переключатель «Задания с письмом» (вкл/выкл).
- Переход после правильного ответа: 1.5 с с тапом «Дальше» в любое место, вместо 4–4.5 с.
- Все иконки действий с текстовой подписью, не только ☰ и ←.

## 3. Технологические решения

### 3.1. Оффлайн: PWA, а не нативная обёртка

Выбор: **PWA** через `vite-plugin-pwa` (Workbox). Причины: нулевая стоимость распространения (та же ссылка на GitHub Pages), работает на iOS и Android, не требует аккаунтов разработчика, вся кодовая база остаётся прежней. Нативная обёртка (Capacitor / TWA в Play Store) возможна позже поверх того же PWA, если понадобится магазин.

Что входит:
- `manifest.webmanifest`: имя «Иврит. Тренажёр», иконки 192/512 + maskable, `display: standalone`, `lang: ru`, `dir: ltr`, `theme_color`.
- Service worker с precache всех ассетов сборки, картинок из `public/pictures/` и аудио. Стратегия `autoUpdate` с баннером «Доступна новая версия, обновить».
- Кнопка «Установить на телефон» в меню: на Android через событие `beforeinstallprompt`, на iOS — экран с инструкцией «Поделиться → На экран „Домой“».
- `navigator.storage.persist()` после установки, чтобы iOS не стирала данные.
- Проверка `base: './'` и путей картинок (сейчас `./pictures/...`) под precache.
- Lighthouse PWA-аудит в CI как проверка регрессий.

### 3.2. Ядро обучения: `src/core/`

Выносим логику обучения из компонентов в чистые модули без React, что сразу делает их тестируемыми:

```
src/core/
  scheduler.ts     // выбор слов для раунда по коробкам и датам
  progress.ts      // чистые функции: applyAnswer(progress, wordId, correct, gameType)
  round.ts         // модель раунда: задания, ответы, итоги, звёзды
  storage.ts       // чтение/запись с версией схемы и миграциями
```

Схема хранения (localStorage, одна запись `hebrew-train/v2`):

```ts
interface Progress {
  version: 2;
  words: Record<string, { box: 0|1|2|3|4|5; due: string; seen: number; correct: number; wrong: number; lastSeen: string }>;
  games: Record<GameType, { rounds: number; bestScore: number; lastStars: 0|1|2|3; answers: Array<{ d: string; c: number; t: number }> }>; // answers по дням, не более 90 дней
  days: Record<string, { rounds: number; correct: number; total: number }>;   // "2026-10-19"
  streak: { current: number; best: number; lastDay: string };
  settings: { fontScale: 1|1.15|1.3; sound: boolean; tts: boolean; typing: boolean };
}
```

Миграция со старого ключа `hebrew-train-stats`: суммарные `correct/total` переносятся в `games[*]`, старый ключ удаляется.

Состояние приложения: React Context + `useReducer` поверх `storage.ts`. Zustand не вводим: зависимостей и так минимум, а объём состояния небольшой.

### 3.3. Резервная копия прогресса

localStorage может быть очищен системой или пользователем. Добавляем экспорт в JSON-файл (через `Blob` + «Поделиться»/скачать) и импорт через `<input type="file">`. Без сервера это единственный способ не потерять прогресс при смене телефона.

### 3.4. Рефакторинг игр

- Общий `GameShell` (шапка с прогресс-полосой, кнопка выхода с подтверждением «Прервать раунд?», область задания, нижняя панель).
- Общий хук `useRound(tasks)` вместо копий `generateNewRound`/`useAutoNext`/`setTimeout` в каждой игре.
- Общий `AnswerFeedback` вместо `SuccessModal` + alert-ов: короткая встроенная карточка под заданием (слово, перевод, озвучка), без оверлея на весь экран.
- Каждая игра становится компонентом `Task*` 80–150 строк, который получает одно задание и возвращает результат через `onAnswer(correct)`.
- Удаляем `useGameLogic.ts`, `HebrewInput.tsx`, `App.css`; `useMatching` и `anagramUtils` переезжают в новые игры.

### 3.5. Навигация

Переходим на `react-router` в hash-режиме (`/#/`, `/#/play/daily`, `/#/progress`). Hash-режим работает на GitHub Pages без 404-трюков и чинит кнопку «Назад» на Android: сейчас она закрывает приложение.

### 3.6. Данные слов

- Валидация `words.json` в тесте: уникальные `id`, обязательные поля, одна из двух картинок задана, эмодзи не повторяется у разных слов, строка иврита содержит только буквы/пробел/гереш.
- Исправления из п. 1.3 (дубль `wind`, `ביצה`, эмодзи для головы/живота/волос/чашки/кастрюли: заменить на картинки в `public/pictures/`, как уже сделано для стола и холодильника).
- Пропуск буквы и анаграммы работают по буквам без пробелов и гереша; при вводе `'` нормализуется в `׳`.
- Поле `difficulty` убираем из типа и данных; сложность определяется коробкой слова, а не словарём.
- Экспорт из JSON в типизированный `words.ts` не делаем: JSON удобно редактировать автору и валидируется тестом.

### 3.7. Качество и поставка

- Компонентные тесты на каждую игру (React Testing Library): правильный ответ, ошибка, завершение раунда.
- GitHub Actions: на каждый push в `main` — `lint`, `tsc`, `vitest`, `build`, деплой на Pages из артефакта сборки. Папка `docs/` перестаёт коммититься (убирается из репозитория, добавляется в `.gitignore`). Если удобнее оставить текущий способ, действие сокращается до проверок без деплоя.
- Служебные `*.md` из корня переносятся в `docs-dev/` (или удаляются, если устарели), README актуализируется.

## 5. Как поймём, что стало лучше

Аналитику на сервер не собираем (принцип проекта). Но локально можно показать пользователю и, при его желании, прислать автору скриншот страницы «Прогресс»:

- доля дней с выполненной «Тренировкой дня» за неделю (цель ≥ 4 из 7);
- число слов в коробках 4–5 через месяц использования (цель ≥ 60);
- доля раундов, доведённых до экрана итогов, а не прерванных (цель ≥ 80 %).

Плюс короткий опрос 3–5 пользователей после этапа 3: «какая игра понравилась, какая надоела».
